# 部署与使用指南

## 1. 准备环境

- 服务端：Linux、Windows 或其他支持 Docker Compose 的环境，首次构建需联网获取依赖；准备足够的磁盘空间备份数据。
- 客户端：Windows 10 1903+ 或 Windows 11 x64、Edge WebView2 Runtime、已登录的 Windows 微信。解析兼容性取决于微信版本与本机文件状态。
- 可选：兼容 Chat Completions 的模型服务与凭据。音频分析需要配置支持音频输入的模型。

## 2. 首次启动服务端

在安装 Python 3 的终端执行：

```sh
git clone https://github.com/w89588/zhiwei.git
cd zhiwei
python tools/init_server_env.py
docker compose --env-file .env config --quiet
docker compose --env-file .env up -d --build
```

生成脚本只创建新的 `.env`，不会覆盖已有文件。该文件包含管理员密码、数据库密码和服务端主加密密钥，应妥善保管，不要公开。默认监听 `127.0.0.1:8787`，在服务器本机访问 `http://127.0.0.1:8787/`；登录名及初始密码分别查看 `.env` 中 `WECHAT_ADMIN_USER`、`WECHAT_ADMIN_PASSWORD`。首次登录后修改密码，创建普通用户，再以普通用户身份创建客户端凭据。

### 局域网访问

默认 Compose 只绑定回环地址。若需要其他设备访问，使用独立 Compose override 将服务端口绑定到可信局域网地址，并在 `.env` 的 `WECHAT_ALLOWED_HOSTS` 中加入实际 IP 或域名。检查防火墙和网络隔离。客户端可以填写 `http://局域网IP:8787`；HTTP 连接凭据和请求不受 TLS 保护，请只在可信网络中使用。公网访问应配置 HTTPS 反向代理和正确的 Host，切勿直接公开数据库端口。

## 3. 配置 Windows 客户端

1. 从 [Release](https://github.com/w89588/zhiwei/releases) 下载 Windows 安装版或便携版，校验 `SHA256SUMS.txt` 后启动。
2. 在服务端“客户端管理”创建客户端，安全保存首次显示的 appKey 和 appSecret。
3. 在客户端“连接设置”填写服务端地址和凭据，确认授权并测试连接。
4. 登录微信，刷新并选择账号。客户端同步群聊和通讯录好友私聊，首次同步可能包含历史记录和可读取的媒体文件。
5. 服务端打开会话、查询消息并选择监听对象。关闭窗口仅收起托盘；退出客户端才会停止同步。

图片显示依赖对应本地图片文件及解密条件；可在客户端设置里按提示提取图片密钥。微信未下载、图片不可用或版本不兼容时，部分媒体可能无法恢复。

## 4. 配置模型和 MCP

在服务端配置你选择的兼容模型和凭据，再选择监听对象并启用分析；媒体分析依赖模型能力和开关。模型提供商会收到分析需要的内容。

在“MCP 接入”创建只读或全部权限 Key，限制授权范围，将页面提供的地址与 Bearer Key 配置到支持 Streamable HTTP 的 MCP 客户端。不要把 Key 提交到公开仓库。演示站没有 MCP 服务。

## 5. 备份、升级和故障排查

- 备份前停止应用写入，同时备份 MySQL、MongoDB、配置与相关存储；服务端主密钥必须与数据配套保存，建议独立加密保管。
- v1.0.0 是新开源仓库的独立版本，Windows 安装目录、启动项和默认数据目录与旧版分开；不会自动迁移旧客户端配置。已有私人部署先完整备份并在隔离环境验证，确认数据库迁移和客户端兼容再切换。
- 无法连接：检查服务运行状态、监听地址、防火墙和 `WECHAT_ALLOWED_HOSTS`；跨设备访问时 `127.0.0.1` 指的是客户端本机。
- 媒体无法显示：确认客户端已登录微信，媒体文件已在本机下载且解密条件满足；不同微信版本的支持情况可能不同。
- 分析没有运行：检查监听状态、模型地址、模型能力、凭据和任务错误；不要在公开 issue 中粘贴真实聊天或密钥。
