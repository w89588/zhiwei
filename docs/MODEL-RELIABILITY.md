# 自动分析、模型用量和故障恢复

自动分析只处理已授权监听的会话。首次监听会为已有消息建立日、周、月、半年和年度等已选择周期任务；一项任务可以包含多个分段摘要、合并、关系记忆和个人画像请求。服务端只在整个任务通过授权、输入版本和配置版本检查后发布结果。

## 用量与成本

- 模型配置中的「回答输出 token 上限」可设置 256–131072，实际模型和接口可能有更低限制。自动分析使用该值和「单次自动分析回答上限」中较小的值；后者默认 2048。这里的 `max_tokens` 含义由服务商和模型决定，不能一概视为包含思考。
- 对已有百炼 `qwen3.8` 配置，如果尚未配置思考模式，默认关闭思考以控制后台整理成本；页面可选择服务商默认、开启或关闭，并可在开启时设置思考预算。其他已有模型维持服务商默认。各服务商是否支持这些可选参数以其接口为准。
- 默认每天最多 100 次自动分析模型请求，可在模型配置中调整。达到上限后任务按上海时间次日自动继续。该限制按请求次数而非费用或 Token 计量；模型测试、回复建议以及其他应用调用不受此限制。超时、断线或未知用量不等于免费；服务商账单是费用依据。
- 为避免上线当天重复消耗，升级前同一天已记录的自动分析用量计入当天请求次数。旧版本未记录的失败请求以及其他程序的调用无法自动计入。
- 模型配置页显示升级后的调用状态、耗时、服务商请求 ID 和能够取得的输入、输出及思考 Token。未知用量明确显示为未知；调用日志不包含聊天、模型正文或 API Key，阶段结果另外加密保存。之前版本缺失的请求信息无法追补。

## 重试和检查点

- 已完成的摘要和合并步骤以用户密钥加密保存，重试时只有在用户、任务、模型配置、提示及实际输入都匹配时才复用；任务最终发布前再次检查授权、租约、监听和任务版本。
- 可明确认定请求未建立连接的错误以及 HTTP 429 限次自动重试。响应超时、中途断线、未知服务端错误和进程中断等可能已经产生费用的情况不自动重放，任务会说明可能已计费。手动重试属于新的调用，可能再次计费。
- 模型返回被截断、无有效文本或格式错误时不将结果视为成功；可取得的用量仍会记录。修改模型配置或收到新消息不会自动重跑已失败任务，需要在自动分析页面明确重试。
- 一次请求已经返回、但在结果检查点保存前发生故障时，系统保守地视为需要确认，避免静默重复调用。无法从旧版本追查的未知请求不受新检查点保护。
- 该机制不保证服务商账单与本系统调用记录完全一致：上游可能已处理请求但没有返回用量，第三方调用也不由本系统控制。模型结果质量、全部历史规模、实际供应商账单及真实微信流量仍需运行验证。
