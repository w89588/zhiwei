# 对话工作台 1.0 产品需求与实现规格

> 历史文档：本文描述 1.0 版本，当前功能和部署请参阅 [项目说明](../README.md)。

版本：1.0.0 · 更新：2026-10-10 · 平台：Windows 10 / 11

## 1. 产品定位

对话工作台是一款以本机微信对话为依据的个人沟通与关系记忆助手。用户主动选择重要的人和群聊，软件持续整理对方、自己以及双方关系的关键信息，让回复更贴合真实背景，并记住聊天里的计划和纪念日。

核心循环：选择会话 → 整理对话 → 审阅知识和日程 → 基于双方记忆生成回复 → 后续对话继续完善记忆。

1.0 的成功标准是这条循环可以完整运行、重启保留结果、自动任务可观察、来源可追溯。知识库采用结构化记录与原文证据，不依赖单份不断膨胀的提示词。

## 2. 用户与典型场景

| 场景 | 用户希望得到的结果 |
| --- | --- |
| 与朋友、家人、伴侣沟通 | 记住偏好、重要经历、表达方式、明确边界和纪念日 |
| 与同事或客户协作 | 保留关系背景、沟通目标、约定、待办与交付计划 |
| 回看自己 | 从自己的发言里发现表达习惯、偏好、目标与行为特点 |
| 持续复盘 | 按日、周、月回看对话，减少重复整理和遗忘 |
| 使用外部 AI | 只让 MCP / SKILL 读取主动加入工作台的会话与相关背景 |

群聊在 1.0 中拥有独立的协作知识库，描述共同背景和约定，不把所有成员混为一个人。跨微信 ID 的联系人自动合并、群成员独立身份解析留待后续版本。

## 3. 信息架构与设计要求

| 入口 | 核心内容与操作 |
| --- | --- |
| 对话工作台 | 添加/移除会话、备注、搜索和筛选记录、背景、回复建议、导出 |
| 联系人知识库 | 独立条目、待确认信息、聊天证据、编辑、日/周/月时间线、手动整理 |
| 我的画像 | 综合已选会话中自己的发言，确认和修正自己的信息 |
| 日历 | 月视图、日程候选、手动日程、年度重复、ICS 导出、CalDAV 设置和同步 |
| 自动化 | 日/周/月设置、整理对象、检查时间、后台运行、执行记录 |
| 连接与配置 | 微信账号、模型接口、外部 AI 读取开关 |

设计沿用简洁的绿色工作台风格：清晰的文字层级、浅色背景、留白、卡片和统一线性图标。参考 ui-ux-pro-max；状态同时提供文字和颜色，推测与确认分开呈现。表单提供可见标签，键盘焦点可见，弹窗可关闭，任务有进度与取消。页面适配窄屏，日历保留七天列，主导航可横向滚动。

## 4. 功能需求

### F01 工作台范围

- 新账号默认没有已选会话。连接微信仅加载必要的账号、联系人和会话目录；只有主动加入工作台的会话可读取、分析、整理或导出。
- 选择、备注与派生数据按微信账号隔离。会话备注最多 2,000 字，可搜索。
- 移除会话立即拒绝后续读取并取消该会话的分析/整理任务。知识、日程和证据从当前可见范围移除；重新加入可以恢复本机保留的记忆。移除不等于物理删除缓存或撤回第三方已有数据。
- 微信按数据库分片保存消息，同一个分片可能包含多个会话；本机解密快照是文件级操作，访问接口仍逐个校验所选会话。原始数据库只读。

### F02 每人独立知识库

- 微信账号与会话 ID 共同确定联系人知识库，不混用同名联系人。
- 条目类别：人物信息、性格与行为、偏好习惯、表达风格、关系背景、边界与禁忌、目标与关注。
- 每条 AI 提取信息附带真实消息 ID、来源会话、发送者、时间和摘录，可跳转到原文所在日期。没有有效证据的条目不入库。
- 状态为待确认、已确认、已忽略。模型归纳标记明确陈述或推测；推测不是心理诊断或人格定论。
- 用户可手动新增、编辑、确认或忽略；人工修改保留内部历史版本，后续 AI 不覆盖人工内容或确认状态。1.0 暂不提供版本回滚界面。
- 相同文本候选合并证据，忽略过的相同候选不重新变为待确认。语义相近但文字不同的信息可能仍需人工合并；矛盾条目由用户审阅与修正。

### F03 本人的知识库

- 每个微信账号有一个“我的画像”。只以本人发言作为自己的自动提取证据，不把对方的发言归给自己。
- 综合当前工作台中的对话，归纳表达习惯、偏好、边界、目标和可观察的行为特点。
- 移出会话后，该会话证据不再展示。完全失去当前有效来源的自动条目不再用于回复；手动补充的本人信息仍属于该账号。
- 本人条目同样可确认、编辑和忽略；待确认推测不作为回复生成的已知事实。

### F04 日、周、月复盘

- 日记：所选北京时间自然日；周记：所在自然周，周一至周日；月记：所在自然月。支持全部本机历史回顾。
- 每次整理生成摘要、对方候选知识、本人候选知识及日程候选。摘要保留决定、待办、未解决问题、关系变化与不确定性。
- 长历史流式读取到临时文件、按预算分段处理并合并，不只读取最近若干条。合并失败、模型返回结构错误或取消时，不提交半成品知识与日程。
- 相同范围消息摘要指纹未变化时复用结果，不重复调用模型。微信迟到消息可通过重新手动整理该日期触发更新。
- 时间线保存周期、范围、消息数、摘要和更新时间，按日期降序查看。

### F05 基于双方记忆的回复建议

- 输入包括用户当前情景、最近上下文、会话备注、人工背景、双方已确认知识、最近周期摘要和既有聊天总结。
- 优先提供明确边界，限制知识和摘要输入体积；最近消息数量与分段字符预算由模型配置控制。
- 输出分析、沟通风险、三条可复制候选与可选追问，匹配本人的表达习惯并尊重对方边界。
- 不自动发送微信消息；用户选择、修改和复制后自行发送。聊天文字和画像作为数据处理。

### F06 周期任务

- 默认关闭。每日、每周、每月可独立开启；对象为全部当前工作台会话或指定已选会话。
- 默认北京时间 08:00 后检查，应用运行时每分钟检查。日任务整理昨天；周任务整理上一个完整自然周；月任务整理上一个完整自然月。
- 周/月在有新的完整周期后执行一次。开机错过时补跑最近一个已完成周期，不自动补齐所有历史周期。
- 持久化完成标记、失败重试时间和执行记录；失败采用退避重试，最长一小时。手动“立即执行”跳过等待时间和失败退避，但消息不变仍复用结果。
- 跨进程租约避免桌面与后台重复整理；任务可取消、错误可查看，账号切换或会话移除停止相关整理。
- 可显式开启 Windows 当前用户后台任务，每 15 分钟运行独立 worker。需要电脑开机、用户登录、数据库和模型接口可用。睡眠/关机不运行，无服务端永久执行承诺。

### F07 日历提取与管理

- 从约定、未来计划、生日与纪念日提取日程，保留聊天依据。按消息实际时间解析“明天”“下周”等相对日期；无法确定日期时保留无日期候选。
- 先进入待确认列表，用户核对时间后才加入正式日历。可手动新建或修改自己的日程，或关联工作台会话。
- 支持标题、开始/结束、全天、地点、说明、不重复/每年重复。全天结束日期为不包含的次日；时间使用北京时间。2 月 29 日的年度重复只在闰年显示。
- 月视图显示正式日程；侧栏区分候选和本月安排。可导出已确认事件的标准 ICS 文件。

### F08 CalDAV 同步

- 1.0 第三方日历接入选用 CalDAV，用户填写服务地址、用户名、应用专用密码，发现并选择目标日历。
- 凭据按微信账号保存，用 Windows DPAPI 加密；设置接口不返回密码。远程要求 HTTPS，本机调试可使用 localhost HTTP。
- 手动同步可用，自动同步默认关闭。开启自动同步后，周期检查上传本人的日程及当前工作台来源的已确认日程。
- 1.0 为单向创建和更新。本地稳定 UID 防止重复创建，首次创建使用 If-None-Match，后续更新使用远端 ETag / If-Match。
- 远端冲突不覆盖，显示冲突供用户到第三方日历处理；网络失败可重试。同步中人工修改保留为待再次同步。更换目标不擅自移动或删除旧日历事件。
- 上传标题、时间、地点、用户日程说明与重复规则，不附带聊天原文证据。说明字段本身会同步，请用户审阅。
- 不支持远端修改自动回流、删除传播、多人共享日历管理、服务商专属 OAuth 或跨域发现。服务需要支持同源 CalDAV 发现/直接集合地址及日程写入；缺少 ETag 的服务可创建但不能安全更新。
- CalDAV 遵循 [RFC 4791](https://www.rfc-editor.org/rfc/rfc4791)，ICS 使用 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)。实际服务账号需要用户配置后验证。

### F09 MCP 与 SKILL

- 外部接入默认关闭；启用后只读当前账号工作台中的会话、备注、背景、双方已确认知识和周期总结。
- 每个请求校验会话成员资格，不能指定未选会话绕过限制。本人自动知识的来源证据同样过滤当前工作台范围。
- 不能通过 MCP 修改知识、日程、配置、读取密钥或发送微信消息。外部应用可将读到的数据发给自己的模型。
- 提供状态、会话列表、分页读取、搜索、背景上下文、分页导出与技能文件。撤销授权立即拒绝后续请求。

## 5. 数据与技术实现

| 数据 | 存储与规则 |
| --- | --- |
| 工作台选择与备注 | 本机 workspace.json，账号分区 |
| 知识、修订、周期摘要、日程、配置、执行记录、租约 | memory.sqlite3，WAL 与原子事务，账号分区 |
| 旧背景与总结 | 首次按最后连接账号迁移到账号分区，保留旧文件 |
| CalDAV 凭据 | caldav.bin，Windows DPAPI 加密 |
| 模型密钥、微信密钥、外部接入发现信息 | Windows DPAPI 加密 |
| 聊天快照和派生内容 | 当前 Windows 用户本地应用目录；不承诺全文加密 |
| 后台执行 | Windows 任务计划 + WechatHelperTasks.exe，沿用当前用户数据目录 |

默认目录为 `%LOCALAPPDATA%\WechatHelper`。可使用 `WECHAT_HELPER_DATA` 指定隔离目录。软件仅监听 127.0.0.1；UI 与外部接入分别鉴权。关闭外部接入不影响本机 UI。

新模块：`memory_store.py`、`knowledge.py`、`calendar_sync.py`、`scheduler.py`、`product_api.py`、`chat_memory.py`、`windows_tasks.py` 与 `tasks_main.py`。保留既有微信读取、图片解析、聊天导出、模型配置和 MCP 实现。

## 6. 验收清单

| 编号 | 验收标准 |
| --- | --- |
| A01 | 空工作台不展示聊天；未选会话的读取、分析和外部请求被拒绝 |
| A02 | 两个账号的知识、旧背景和总结互不混用；重启保留知识与日程 |
| A03 | 自动知识有真实消息依据；对方发言不能成为本人条目的依据 |
| A04 | 确认/修正后回复上下文包含双方知识；待确认信息不作为事实使用 |
| A05 | 日/周/月正确处理北京时间、跨年自然周、闰年；重复整理不重复调用模型 |
| A06 | 模型错误、取消、会话移除不提交半成品；人工修改不会被覆盖 |
| A07 | 周期任务默认关闭；租约互斥、完成去重、失败重试和执行记录可验证 |
| A08 | 候选不上传；ICS 日期与年度重复正确；CalDAV 创建/更新条件请求及冲突正确 |
| A09 | CalDAV 密码不以明文写入文件或返回接口；移出的会话不再参与新同步 |
| A10 | 375 / 768 / 1024 / 1440 宽度页面可用，弹窗不越界，长文本不造成全页溢出 |
| A11 | 发布目录包含桌面程序、MCP、后台 worker、技能与启动说明，无个人数据 |
| A12 | 检测常见本机 AI 客户端，选择后按各自格式预览并配置 MCP，可同时安装支持的 SKILL |
| A13 | 保留其他设置及 JSONC / TOML 注释；备份、同名冲突确认、预览过期/文件变化保护可验证 |
| A14 | 写入不改变外部读取开关或客户端信任规则；MCP 和聊天数据无法调用配置写入接口 |

### AI 客户端接入补充（2026-10-11）

支持 Codex、Claude Desktop、Claude Code、Cursor、Windsurf、Devin Desktop 的 Cascade 以及 VS Code 默认用户配置。分别使用官方定义的 TOML / JSON / JSONC 字段，配置条目固定为 `wechat-helper`。Codex、Claude Code、Cursor 可同时安装 `wechat-chat` 技能。检测使用已知文件、目录和命令入口，呈现依据而不把发现目录当作连接成功。未检测到、自定义配置位置、其他 VS Code 配置档案和远程窗口保留手动入口。

流程为检测、主动选择、预览、写入、客户端重新加载及 `wechat_status` 验证。十分钟预览凭证只可使用一次，绑定文件原始内容与当前 MCP 安装路径；原文件变化时重新预览。更新前在原路径旁生成备份，用户修改过的同名内容需明确选择替换。多文件写入失败会报告已写入路径和备份，方便继续配置或回退。界面 API 仅可由工作台使用，不暴露完整客户端配置或其中的凭据。

技能自身先检查工具存在性，再诊断工作台运行、接入开关、账号连接与选定会话。已有用户授权及本机操作能力时可协助界面配置；仅安装技能不等于授权安装程序或读取全部微信历史。客户端权限提示继续由客户端处理。

配置依据：[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)、[Claude Code MCP](https://code.claude.com/docs/en/mcp)、[Claude Desktop 本地服务](https://modelcontextprotocol.io/docs/develop/connect-local-servers)、[Cursor MCP](https://cursor.com/docs/mcp)、[Devin Cascade MCP](https://docs.devin.ai/desktop/cascade/mcp)、[VS Code MCP](https://code.visualstudio.com/docs/agent-customization/mcp-servers)。Windsurf 旧目录兼容既有安装，迁移后的 Devin 配置使用独立目标。

## 7. 后续版本方向

语义去重与知识冲突解决、按人物合并多会话、知识版本回滚和删除管理、长周期历史补跑、CalDAV 双向同步与删除传播、更多提醒方式。1.0 优先实现可控、可追溯的完整循环，不以未经确认的性格推断代替用户自己的判断。
